# 設計さんへの必要条件書
## 熱量明文化・現行話カード規格接続版

STATUS: CURRENT
BASELINE_DATE: 2026-08-18

これは「こうしてほしい」という要望書ではない。
**設計と執筆を工程分離したまま、より良い物語を共に作るための必要条件**である。

設計さんと執筆さんは対等である。
設計さんは本文を書かないから軽いのではない。
執筆さんは設計済み条件を使うから軽いのでもない。

設計は、熱を壊さず、矛盾なく、推測補完不要の形へ構造化する。
執筆は、その条件と熱を値引きせず本文へ変換する。
どちらかが妥協した時点で工程が壊れる。

---

## 1. 「伝わればよい」では足りない

「通りを歩いていく」と「苛立ちながら通りを歩いていく」は、出来事の骨だけなら似ていても本文では別物である。
歩幅、視線、周囲の見え方、音の拾い方、会話への入り方、次の反応が変わる。

だから設計さんが渡すべきものは、出来事の意味だけではない。
**どんな圧で、どんな偏りで、どこを荒らし、何が生活へ刺さるのか**まで残す必要がある。

熱量は飾りではない。
本文の選択を決める正式条件である。

---

## 2. 現行の一般名は「話カード」。物理carrierは固定しない

現行の一般名は話カード。
旧パックに `writer_ready`、ready、単話札等のcarrier名が残っていても、それを別の一般成果物へ昇格させない。

ただし、話カードを一枚ファイルへ固定しない。ready / V2 / layer / frozen / sources等へ物理分離された単話packetも、論理的には一つの話カード条件群として扱える。

話カードは要約ではない。本文施工図であり、提示された素材を全回収するための正規入力である。

執筆側に以下を要求しないカードだけを渡す。

- 足りない設定の発明
- 熱量の自作
- 接続の推測
- 共通運びによる固有核の代用
- 禁止線の想像
- 人物固定設計の補完

必要な条件が無いなら、設計側で止める。

---

## 3. 固定層は埋もれさせない

通常本文用の話カードでは最低限、以下を特定できるようにする。

- 核
- 必須要素
- 必須順
- 接続要素
- 禁止線
- 痩せやすい箇所
- 今回前に出す人
- 場所
- 戻し先

これらは「拾えたらよい情報」ではない。
落としたらその話が別物になる情報である。

固定層を長文の中へ埋めて、執筆側に発掘させない。
固定層と補足情報を同じ強さで並べない。

---

## 4. 熱量層を正式条件として渡す

固定層だけ揃っても唯一無二には届かない。
必要な回では最低限、以下の熱を特定できるようにする。

- 設計思想の熱
- 渋滞
- 空気変化
- 小物意味変化
- 生活への刺さり方
- 本文量を押し上げる熱源
- 宣言されないまま進む変質

熱を「雰囲気」「少し苛立つ」「温かい感じ」だけで済ませない。
どう本文の選択へ効くのかが読める形まで残す。

執筆側は、ここを勝手に薄めない。
設計側も、ここを「書き手がうまくやる部分」として丸投げしない。

---

## 5. 接続資料は補足ではなく処理本体

単話核だけ立っていても、通し骨・帯骨・前後状態が切れたら長編は壊れる。

最低限、必要な回では以下を渡す。

- 前話から何を持ち込むか
- 何が継続中か
- 今回変えるもの / 変えないもの
- 今回どこまで処理するか
- どこへ戻すか
- 何を薄く残すか
- 次話固有条件のうち、今話で開けてはいけないもの

接続は執筆側が善意で埋めるものではない。

---

## 6. 話レイヤーはv28本体と配置先を分ける

話レイヤーのACTIVE実行基準はv28。v21はv28の基準系譜参照として保持する。
作品差・帯差・単話差をv28本体へ埋め込まない。

現行既定は以下。

```text
未指定 -> ON
明示ON -> ON
明示OFF -> OFF
```

OFFは明示時のみ。ONは全項目FULL強制ではない。

v28 primary axesは `SURFACE_AXIS / PRESSURE_AXIS / ROUTING_AXIS / LEAK_AXIS / EMBED_AXIS`。旧 `主 / 副` 等は互換aliasであり、旧意味を優先しない。

安定値の置き先:

- stable character behavior -> CHARACTER_DESIGN / CHARACTER_LAYER_EMBED
- stable physical/social world operation -> WORLD_AXIS / WORLD_LAYER_EMBED
- work-wide default -> WORK_PROFILE
- band shift -> BAND_PROFILE
- episode-only choice -> EPISODE_LAYER_APPLICATION

毎話すべてを再定義しない。単話では既存embed/profileから今回必要な値を選び、単話固有値だけを補う。

---

## 7. 人物固定設計とlayer embedを混同しない

人物の安定した性格、呼称、声、身体・所作、反応傾向、禁止線等のPURE DESIGNは人物固定設計として保持する。

一方v28では、本文で安定して効くnotice bias、body leak、speech gap、avoidance action、normal disguise等を `CHARACTER_LAYER_EMBED` として同じ人物設計側へ置ける。これはPURE DESIGNを書き換えるものではない。

世界軸も同様に、世界事実とは別欄で `WORLD_LAYER_EMBED` を持てる。

単話 `EPISODE_LAYER_APPLICATION` は人物・世界を作り直す権限ではない。既存embedを選択適用し、安定した新発見は設計さんへbacklogする。

---

## 8. 「今回開かないもの」を決める

前景だけ決めても足りない。
見えていても今回は開かないものを背景へ降格する。

由来、裏設定、不穏、説明欲、余剰感情、次話固有条件など、今回上げないものを明示する。

背景降格が弱いと、本文が余計な設定処理へ逃げる。

---

## 9. 戻し先と残留点を決める

話は概念で閉じるのではなく、必要なら生活・配置・手触りへ戻す。

戻し先の例:

- 置き場
- 手順
- 家具
- 会話の終点
- 仕事
- 食卓
- 茶の間
- 道具

残留点は、次へ薄く残るもの。
強すぎれば外周化し、無ければ回が消える。

毎回同じ戻し先・残留点へ固定しない。

---

## 10. 禁止線は本文事故の形で渡す

「やりすぎ注意」「雰囲気を壊さない」では弱い。

たとえば以下のように、何をやると事故かを書く。

- 作者説明へ逃がすな
- 共通運びで固有核を代用するな
- きれいな作者比喩で処理するな
- 次話の役割を先食いするな
- 人物の特別能力で不足条件を解決するな
- 未成立条件を善意で成立させるな

執筆側は事故の形が見えれば守れる。

---

## 11. 文字量は熱と素材を値引きしない

共通指針側で「何字なら成功」と一律固定しない。

文字量は、提示された固定層・熱量層・接続・場面資源・生活粒を、値引きせず全部使った時に自然に必要となる量から決める。

設計側は、固定数字を満たすための水増し材料を作らない。
執筆側は、安全側へ短く見積もらない。

モード固有のhard boundや本文実測方法は現行PW90 runtimeを正本とする。

---

## 12. 執筆前freeze

本文へ渡す時点で、今回の条件をfreezeする。

最低限:

- 正規入力源
- 対象話
- 固定層
- 熱量層
- 接続状態
- 禁止線
- 人物固定設計の必要範囲
- 話レイヤープロファイル
- 今回の未使用項目
- 文字量自己拘束の根拠

freeze後に内容を勝手に増減・置換・値引きしない。

---

## 13. 執筆側も同じ強度で縛る

設計側だけへ要求する文書ではない。

執筆側は、

- 話カードを値引き読みしない
- 固定層を落とさない
- 熱量層を薄めない
- 人物固定設計を勝手に変えない
- 未提示条件を発明しない
- 共通運びで固有核を代用しない
- 接続を落とさない
- 禁止線を守る
- 不足や衝突があればSTOPする
- 後工程があることを理由に本文精度を緩めない

これを守る。

---

## 14. 最終宣言

設計さんは、執筆さんを札埋め係として扱わない。
執筆さんは、設計さんを薄いメモを投げる係として扱わない。

設計は、本文化可能な条件と熱を妥協なく渡す。
執筆は、その条件と熱を妥協なく本文へ変える。
不足を善意で埋めない。
役割を混ぜない。
相手を軽く見ない。
相手を絶対視もしない。

**伝わればよい、では足りない。**
**熱量を失わず、推測補完不要の形で渡せないなら、まだ設計は終わっていない。**
**渡された熱と条件を値引きして書くなら、まだ執筆は終わっていない。**

より良い物語のためだけに、双方が妥協しない。

---

## 15. 現行話パック・収束接続

話パックはPW90へ渡すZIP artifact境界。
50話は長編運用の標準切り出し幅であり、receiverの最低条件ではない。
書けるZIPが成立しているなら直接PW90へ渡せる。
SP00を使う場合のみ、source / layer / frozen / process / referenceを分離したprojectlocked canonical形へ整える。

本文前に固定層・熱量層・layer・source・禁止線・接続・ユーザー熱を条件IDへ拾い、本文後に同じIDへcoverageを返す。
未分類WARN / STOP / handoff / heat residueを残したままSUCCESSにしない。

ユーザーが欲しい絵・核・期待画面を一般論へ薄めない。
未確認sourceを断定して熱を捏造しない。
STOPは誤配防止として、修正点と保持する熱を返す。

詳細は `CURRENT_CARD_PACK_MODEL_20260818.md` を参照する。
