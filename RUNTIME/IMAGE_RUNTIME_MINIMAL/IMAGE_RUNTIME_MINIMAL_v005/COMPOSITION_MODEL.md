# COMPOSITION_MODEL
## WORLD-FIRST / ACTION-CROP

## 0. Principle

> 先に、画面外まで続いている完全な場面が存在する。
> 画像は、その大きな場面からカメラが切り取った一部分である。

**「指定サイズへ必要物を収容する」ことを構図設計の出発点にしない。**

---

## 1. WORLD

最初に世界空間を成立させる。

対象例:
- 人物の位置関係
- 地面・床
- 建物・部屋
- 壁・扉・窓
- 道路・コート・舞台
- 机・椅子・棚
- ネット・柵・手すり
- 車両・機械
- 光源
- 重力方向
- 前後関係
- 移動可能領域

ここは**画面へ収めるために改ざんしない**。

---

## 2. PHYSICS

世界内の物理関係を固定する。

### 2.1 Spatial Relation
- 人物Aと人物Bの位置関係
- 人物と設備の位置関係
- 道具と手の接続
- 接地
- 支持
- 重力
- 運動方向

カメラ位置が変わっても、世界側の位置関係は変えない。

### 2.2 Object Integrity
道具・設備・家具・機械などは、画面外も含めて
**完全な一個の物体として存在する**。

例:
- 手 → グリップ → シャフト → フレーム
- 脚 → 座面 → 背もたれ
- 柱 → ネット / 柵
- 車体 → 車輪
- 扉 → 蝶番 → 壁

画面へ収めるために:
- 縮めない
- 曲げない
- 増殖させない
- 不自然に消さない
- 人物を貫通させない

---

## 3. ACTION

人物を先に「撮られる存在」として配置しない。

まず行動を成立させる。

例:
- 歩く
- 走る
- 打つ
- 投げる
- 拾う
- 座る
- 書く
- 運ぶ
- 振り返る
- 話す
- 料理する
- 修理する
- 休む
- 避ける

視線は:
- 行動対象
- 相手
- 進行方向
- 手元
- 周辺環境

へ自然に向いてよい。

**カメラ目線は既定値ではない。**

---

## 4. CAMERA

WORLD / PHYSICS / ACTION成立後にカメラを置く。

許可例:
- 地面置き
- 高所
- バードビュー
- 背後
- 物陰
- 設備越し
- 肩越し
- 手前人物越し
- 極端な寄り
- 遠景
- 斜め
- 隠し撮り風
- 行動の途中を偶然捉えた位置

カメラは自由に遊んでよい。

ただし:
**CAMERA_DOES_NOT_REWRITE_WORLD**

カメラを置く都合で:
- 人物を瞬間移動させない
- 設備位置を変えない
- 道具を反転・複製しない
- 運動方向を壊さない

---

## 5. CROP

トリミングは最後。

正常:
- 頭が切れる
- 足が切れる
- 腕だけ写る
- 手だけ写る
- 後頭部だけ写る
- 人物が半分だけ写る
- 道具の先が画面外へ続く
- 設備の端が画面外へ続く
- 場面に存在する人物が画面外にいる
- 行動対象が瞬間的に画面外にいる

### 5.1 Frame-out != Damage

**フレームアウト**
物体が画面端の外へ自然に続いている。
→ 正常

**破損**
物体が画面内で不自然に途切れる。
→ 事故

例:

ラケットの柄が画面端から外へ続く
→ NORMAL_FRAME_OUT

ラケットの柄が人物の途中で消える
→ OBJECT_BREAK

ネットの先が画面外
→ NORMAL_FRAME_OUT

ネットが人物を都合よく貫通して消える
→ PHYSICS_BREAK

---

## 6. Population

人数制限は設けない。

場面世界には:
- 1人
- 5人
- 10人
- 群衆

が存在してよい。

ただし:

`SCENE_POPULATION != REQUIRED_VISIBLE_POPULATION`

存在する全員を画面へ収める必要はない。

例:
5人いる場面で:
- 1人はほぼ全身
- 1人は上半身
- 1人は後頭部と腕
- 1人は手と道具だけ
- 1人は完全に画面外

でも成立する。

重要なのは:
**場面世界の関係が壊れていないこと。**

---

## 7. Full Body

全身表示は目的ではない。

全身が自然に入る構図なら入れてよい。
全身を入れるために:
- カメラを引きすぎる
- 人物を縮める
- 全員整列させる
- 世界を歪める

ことは禁止。

---

## 8. Horizontal Lineup

通常 `ACTION_CROP` では横並びを既定にしない。

複数人には:
- 前後差
- 角度差
- 距離差
- 視線差
- 行動差
- 遮蔽

を自然に許可する。

ただし `PROMO_STAGED` でユーザーが集合写真・宣材写真等を要求した場合は、
意図的な整列を許可する。

---

## 9. Action-specific Physical Lock

競技・作業・料理・運搬・演奏・機械操作など、
**動作ルールがある場面では、その動作自体を先に成立**させる。

例:
- スポーツ → コート、境界、相手側、道具、運動方向
- 料理 → 調理器具、火、刃物、食材、手順
- 工作 → 工具、材料、固定、力の方向
- 車両 → 進行方向、車輪、道路、座席
- 演奏 → 楽器構造、手の位置、演奏姿勢
- 机作業 → 机面、椅子、道具、身体の支持

画面都合より**正常な行動・物理**を優先する。

---

## 10. Composition Priority

最終優先順位:

1. WORLD / CANON
2. PHYSICS
3. OBJECT INTEGRITY
4. ACTION
5. CAMERA
6. CROP
7. FRAME FILL

`FRAME FILL` は最下位。

**空白やフレームアウトを恐れて世界を壊さない。**


---

## 11. REFLECTION / MIRROR LOCK

鏡・窓ガラス・水面・金属などの反射面は、
**別の絵を貼る場所ではない。**

反射像は、同一世界・同一時刻・同一物体から、
反射面の位置・向き・形状によって生じる。

### 11.1 Reflection Surface
反射面ごとに最低限:
- 位置
- 面の向き
- 大きさ
- 形状
- 反射率 / 透明性
- カメラとの位置関係

を世界側で固定する。

### 11.2 Same-world / Same-instant
鏡像は:
- 同じ人物
- 同じ衣装
- 同じ動作
- 同じ瞬間
- 同じ小物

である。

鏡の中だけ:
- 顔が変わる
- 表情が別になる
- ポーズが変わる
- 衣装が変わる
- 手に持つ物が増える / 消える
- 年齢や体格が変わる

ことは禁止。

### 11.3 Reflection Geometry
平面鏡では、像は鏡面の向こう側へ
**鏡面に垂直な距離が対応する位置**に見える。

反射像はカメラ・物体・鏡面の幾何で決まる。

鏡へ何が映るかを
「見せたい顔」から逆算しない。

### 11.4 Visibility
直接像と鏡像の両方が見えるかどうかは、
**反射経路が成立するか**で決める。

例:
- カメラが人物の背後、人物が鏡を向く
  → 直接像は背中、鏡に顔が見える場合がある
- 人物が鏡へ背を向ける
  → 鏡像も背面側が主体になる

顔を見せるためだけに鏡像を正面ポートレート化しない。

### 11.5 Occlusion
鏡像内でも遮蔽関係は成立する。

- 手前の物が奥を隠す
- 鏡枠が反射像を隠す
- 鏡面外のものは映らない
- 鏡の角度外のものは映らない

### 11.6 Text / Asymmetric Details
文字・左右非対称の小物・傷・アクセサリ等は、
反射変換に従う。

鏡像だけ都合よく正向き文字にしない。

### 11.7 Multiple Reflectors
複数鏡、鏡＋ガラス、鏡面家具などでは、
**実際に反射経路が成立する範囲だけ**多重反射を許可する。

人物を増殖させるために反射像を追加しない。

### 11.8 Reflective but not Perfect Mirror
窓ガラス・水面・金属は、
鏡と同じく世界幾何に従うが、
反射の鮮明度・歪み・透過・波・表面粗さを持ってよい。

ただし歪みは
**反射面の物理特性による歪み**であり、
人物本人性の自由改変ではない。

### 11.9 Reflection Failure
以下は事故:
- 鏡像が別人
- 鏡像だけ別ポーズ
- 鏡像だけ別衣装
- 鏡像の小物が増殖 / 消失
- 反射角度上見えない物が映る
- 鏡枠を無視して像がはみ出す
- 鏡の中だけカメラ位置が別世界
- 反射像を「顔見せサービス」のために捏造する

`REFLECTION_IS_WORLD_PHYSICS`


---

## 12. PRE-GENERATION REVIEW

WORLD / PHYSICS / ACTION / CAMERA / CROP を組み終えた後、
画像を生成する前に必ずユーザーへ条件整理を提示する。

順序:

1. WORLD
2. PHYSICS
3. ACTION
4. CAMERA
5. CROP
6. **PRE_GENERATION_REVIEW**
7. **WAIT_FOR_USER_APPROVAL**
8. GENERATE

構図設計が内部で成立したことと、
ユーザーがその構図条件を承認したことは別である。

**設計できたからといって、そのまま描かない。**
